= Touchstone tests

The chart contains a chainsaw end-to-end test in `test/touchstone`, run with `just touchstone` against a running athanor cluster (`just ignite` in athanor, `KUBECONFIG` pointing at it).
It publishes the chart to the in-cluster registry, lets chrysopoeia generate the CRD from it, claims an instance and checks the release.
A touchstone is the dark stone an assayer streaks gold across to read its purity, which is what the test does to a reagent.

PRs run the touchstone tests automatically, through athanor's `touchstone` composite action.

The shared steps live in `test/touchstone/shared/claim.yaml`, a chainsaw step template.
A new test is a folder with three files:

* `chainsaw-test.yaml`: a step with `use.template: ../shared/claim.yaml`.
* `instance.yaml`: the claim and the values to test.
* `assert.yaml`: what must exist once the release is ready. `$instanceNs` is the namespace the chart was released into.

The claim is called `instance`.
To change the name, pass an `instance` binding with `use.with.bindings`.
Steps after the template do not see its bindings.

The generated CRD's API group carries a short hash of `values.yaml` (the file the schema is generated from) and of the namespace chainsaw creates for the test.
Every test therefore gets its own group and CRD, so tests running side by side, whether siblings of one run or two runs on a shared cluster, cannot clash.

All tests are generic and only check that the chart installs and renders properly.
Reagent specific tests and asserts are to be added by a service maintainer.
